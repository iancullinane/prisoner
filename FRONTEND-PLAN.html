Goal

Turn web/ from a single Players screen into a small multi-page SPA covering Players, History, and Play, with a cyberpunk-terminal visual identity (black background, neon-green accent, US Army display font) and a responsive left-sidebar navigation.

Architecture

Routing

react-router-dom. Routes: /players (default), /history, /play.

Styling

Tailwind CSS v4 via @tailwindcss/vite, replacing ad-hoc CSS. Content globs over src/**/*.tsx.

Layout

Layout renders a Sidebar (fixed left nav on desktop, collapses to a top bar below md) + <main> with <Outlet />. Active nav item highlighted in orange.

Fonts

US Army Bold/Regular/Light .ttf in web/src/assets/fonts/, loaded via @font-face in src/theme.css, registered as font-army.

State

Each page fetches independently on mount — no shared player context. Roster is small; redundant fetches are cheap.

API Versioning & Infra

collision SPA routes vs. the deployed Ingress

sheeta-games/k8s/backend-ingress.yaml currently routes the exact path prefixes /players, /play, and /history straight to the Go backend Service, bypassing the SPA entirely. That collides head-on with the planned SPA routes: a hard refresh or deep link to /history would hit the backend and get raw JSON instead of the React app, and /play has no GET handler at all (only POST) — it would 404.

Fix: version the API under /api/v1

All business routes in api/server.go move to /api/v1/players, /api/v1/players/{name}, /api/v1/history, /api/v1/history/{id}, /api/v1/play. /healthz stays unprefixed — ALB target-group health checks hit the pod port directly via the alb.ingress.kubernetes.io/healthcheck-path annotation, never through an Ingress path rule. Frontend API modules prefix their fetch paths with /api/v1; VITE_API_BASE_URL semantics are unchanged.

Infra follow-up (separate repo: sheeta-games)

The Ingress's three path rules collapse into one: path: /api, pathType: Prefix → prisoner-backend. Prefix matching is segment-based, so /api also matches /api/v1/players — any future endpoint under /api/v1/* routes correctly with zero further Ingress edits. The / catch-all → frontend is unchanged, and /players//history//play now fall through to the SPA as intended.

Deploy sequencing: the versioned backend/frontend images and the Ingress change must land together — deploying one without the other 404s API calls for the window in between. Ships as its own PR in sheeta-games, coordinated with the prisoner release.

Components & Data Flow

PageFetchesBehavior
PlayersPage GET /api/v1/players Thin wrapper around existing PlayerManager (list + create-player form), restyled with Tailwind.
HistoryPage GET /api/v1/history, optional GET /api/v1/history/{id} Table of interactions (player IDs, moves, played-at). Optional player filter <select> sourced from GET /api/v1/players.
PlayPage GET /api/v1/players, POST /api/v1/play Two dropdowns (Player A/B) + Cooperate/Betray button pairs per side. Submit disabled while in-flight; shows returned scores on success.

New API modules

Same pattern as existing api/players.ts: fetch, throw Error with status on !response.ok, return parsed JSON.

  • api/history.ts — listHistory(), listHistoryForPlayer(id)
  • api/play.ts — playRound(req): Promise<PlayResponse>

Error Handling

Pattern

Each page owns local error: string | null state (same as PlayerManager today), rendered as <p role="alert">. No global error boundary this pass.

guard Double-submit

PlayPage disables its submit button for the duration of the in-flight request, re-enabling on both success and failure.

Self-play guard

Server already enforces player-cannot-play-itself (400). UI additionally disables submit client-side when Player A === Player B to skip the round-trip.
